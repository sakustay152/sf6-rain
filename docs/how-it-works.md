# 它是怎么认出「我方黄血」的

这篇文章讲 `src/Detector.cs` 和 `src/MonitorEngine.cs` 里的实现细节。所有阈值都可以在代码里找到，欢迎按自己的 HUD 调整。

## 0. 设计约束

- **不读内存、不注入、不 Hook**：只用 GDI 把游戏窗口的客户区画到一张位图上。游戏更新、反作弊、崩溃都与本工具无关。
- **不假设我方在左或在右**：靠 HUD 自带的白色「我」字判断。
- **失败要安静**：认不出方位、画面全黑、黄色过宽时一律不触发，而不是猜。

## 1. 取帧

`ScreenCapture.Capture(hwnd)`：

1. 用 `GetClientRect` + `ClientToScreen` 得到客户区在屏幕上的矩形。
2. `Graphics.CopyFromScreen` 复制这一块像素（物理分辨率，已含高 DPI）。
3. 抽样判断是否「几乎全黑」。是的话再试一次 `PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT)`，兼容部分渲染模式。
4. 窗口最小化、尺寸异常、已销毁时返回中文错误，状态机只更新 UI，不触发。

预览每 130 ms 缩放到 960 宽推到界面；检测仍然用原始分辨率。

## 2. 定位血条带

`FindBand` 不靠模板匹配，只利用 SF6 HUD 的几何不变量：

```
y: 画面高度的 3.5% ~ 24%
x: 从画面中心向外扫，左右各 3.5% 宽度以内跳过（中间的计时器区域）
```

- 对每一行，从中心向外找到第一段连续 ≥4% 画面宽度的「彩色像素」（`Kind` 区分青/紫/黄/绿等，忽略背景和白色）。
- 左右内缘必须近似对称：`| (w - innerR) - innerL | <= 2% * w`。
- 把这些行按连续高度聚类，取最高的一段；行内取内缘的中位数，并重新对称化。
- 从内缘向外量彩色段长度（允许 0.8% 宽度的间隙），得到血条全宽；若宽度不合理（<0.45h 或 >0.55w），退回到按高度估算的先验值（宽高比 ≈ 1.6:1）。
- 学到的几何按画面宽高比存进 `config.json` 的 `layouts`，下次同分辨率直接命中。

被特效短暂遮挡时，位置缓存保留 900 ms。

## 3. 判断哪条是我的

血条上方、靠近外侧的位置有白色「我」字。实现只数白色像素：

- 对每条血条，采样外侧 80% 的横向范围、中间一半的高度。
- 白色判定：`max(R,G,B) >= 205` 且饱和度 `(max-min)/max <= 0.15`。阈值收紧到 0.15 是为了不把黄色填充的高光当成白字。
- 一侧白点数量 ≥ `max(12, 0.00002*h²)` 且达到另一侧的 2 倍，判为强信号。
- 方位记忆 1.5 秒；连续 3 帧出现相反强信号才切换，避免左右横跳。
- 手动模式或规则页强制左/右时，跳过这一步。

## 4. 量黄色

`MeasureYellow` 对血条内部 30%~70% 高度的每一行：

- 找最长的一段黄色像素（允许 3 像素断裂）。
- **内缘锚定**：黄段必须触及血条内缘（±6% 宽）。这条约束让画面里其他黄色场景（灯光、招牌、火花）无法冒充血条。
- 记录每一行黄段长度的中位数，除以血条全宽得到黄色占比。

判定：

| 条件 | 结果 |
|---|---|
| 命中行数 ≥ 55%，且占比 ≥ 2% | `Yellow = true` |
| 占比 > 60% | `YellowTooWide = true`，忽略（自定义 HUD 常见） |
| 其他 | 不触发 |

对手那条血条也照常测量，只用于预览上色，不参与触发。

## 5. 状态机

`MonitorEngine.Step` 每个采到的帧跑一次（默认 20 fps）：

```
        黄血持续 0.35s                播放结束 / 血条恢复
ARMED ─────────────────► PLAYING ─────────────────► ENDED
  ▲   │                     │                          │
  │   │ 只闪一下             │ F9 急停                  │ 血条恢复
  │   ▼                     ▼                          ▼
  └── HOLD（不触发）      ENDED（等恢复） ◄────────── ARMED
```

- **HOLD**：黄色持续不足 `yellow_hold_seconds`（默认 0.35 s）时只显示「马上播放」。
- **PLAYING**：触发后把黄色占比、方位、曲名写进日志，并请求 UI 播放。
- **恢复**：非黄状态持续 `clear_seconds`（默认 1.2 s）后淡出停止，进入冷却并重新待命。
- **单曲结束**：若开启 `loop` 且血条仍黄，直接接下一首；否则进入 ENDED，等血条恢复再待命。
- **失败**：连续失败 ≤3 次时 2.5 s 后重试，超过则停下并提示检查 `music` 文件夹。
- **急停（F9）**：立刻停声并解除待命，直到血条恢复。

## 6. 播放

`AudioPlayer` 用 WPF 的 `MediaPlayer`（Windows 自带，不需要额外解码器），在 UI 线程创建，配一个 40 ms 的 WinForms Timer 做 smoothstep 淡入淡出。

- 淡出过程中不报告「播放结束」，避免把主动停止当成歌曲结束。
- 停止/切换时媒体引擎可能补报一次失败（实测 0xC00D11B1），所以只有 `IsPlaying == true` 时的 `MediaFailed` 才算真失败。
- 音量、播放顺序、「优先雨爱」都由 `MusicLibrary` 处理；音乐库递归扫描 `music`，忽略小于 4 KB 的文件。

## 7. 界面

- WinForms 全自绘暗色主题；`NumberBox` / `SelectBox` / `DarkList` 都是自己画的，避免原生控件在 150% DPI 下的白底和白滚动条。
- `DeviceDpi` 在这台机器上不可靠，所以按 `GetDpiForSystem()` 手动算 `_uiScale`，所有坐标走 `S()` / `SRect()`。
- 预览面板会把检测到的血条框、白字计数、黄色占比画在画面上，方便你判断阈值是否合适。

## 8. 测试

- `SelfTest.Run()`（程序里点「自检」）：合成 720p/900p/1080p HUD，覆盖满血、17% 黄血、左右镜像、无「我」字、整条黄色、手动框，共 8 项。
- 开发期还有两个不随仓库发布的 harness：
  - 状态机：用合成 `Detection` 驱动 `Step`，验证 HOLD/触发/恢复/冷却/急停。
  - 端到端：建一个无边框窗口显示真实游戏截图，`PrintWindow` 抓回来再跑检测，验证「抓帧 → 识别 → 状态机」链路。真实截图只在本机使用，不进入仓库。

## 9. 已知限制

- 全屏独占模式抓不到，必须无边框窗口。
- 自定义 HUD 若把黄色画得和血条不一致，可能被「过于宽」规则拒绝，此时请用规则页的手动框选。
- 分辨率或宽高比变化后，第一帧可能按估算宽度工作，几帧内会重新学习。
